## 2025-02-15 - Strict Input Length Constraints for Persisted Client States
**Vulnerability:** Lack of input length constraints on client-side forms allowed arbitrarily large payloads (prenom, telephone, besoin, address) to be accepted, processed, and persisted. This posed a risk of client-side Denial of Service (DoS) and memory/localStorage exhaustion.
**Learning:** React Hook Form and Zod schemas were configured to check only minimum lengths or valid structures (e.g. valid phone numbers), leaving payload sizes unbounded. Since the entire multi-step questionnaire state is serialized to a single string and auto-saved to `localStorage` on change, memory limits and serialization performance could easily be degraded by oversized malicious strings.
**Prevention:** Always pair standard custom refinements (like phone validation) with maximum string length bounds (`.max()`) in Zod schemas, and enforce them symmetrically on the JSX inputs/textareas via the `maxLength` attribute. This guarantees defense-in-depth at both the layout and validation layers.

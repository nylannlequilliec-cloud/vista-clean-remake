## 2025-07-27 - [Client-Side DoS via localStorage Persistence in Next.js/React Forms]
**Vulnerability:** The application implements automated state synchronization by watching form state and persisting it to `localStorage`. Because the form inputs (prenom, telephone, besoin, address) lacked maximum-length validation both in Zod and HTML attributes, an attacker or oversized input could exceed the browser's origin quota (typically 5MB). This triggers a `QuotaExceededError` exception, crashing the client application and locking the user out of the site.
**Learning:** Persistent local state mechanism without boundary checks creates an easy Denial of Service vector. Boundaries must be enforced at both the validation layer (Zod) and UI layer (HTML inputs) to guarantee state payloads never exceed persistence boundaries.
**Prevention:** Every synchronized form field must have strict `maxLength` attributes in HTML inputs alongside `.max(...)` boundaries in the underlying Zod schema to prevent unchecked state expansion before serialization and persistence.
